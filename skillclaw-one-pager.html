核心问题与理念

AI Agent 在日常使用中积累了大量经验，但这些经验散落在各个会话、各个 Agent、各个设备中，无法复用和进化。SkillClaw 通过自动从真实会话中提取、去重、改进和验证技能（Skill），实现跨会话、跨 Agent、跨设备、跨用户的技能集体进化。用户只需正常聊天，技能进化在后台静默进行。

系统架构 — 双组件模型

组件功能部署
Client Proxy本地 API 代理，拦截请求、记录会话、管理本地技能库每人一个
Evolve Server读取会话数据，自动进化/创建技能并写回每组一个

两组件通过共享存储层通信（Alibaba OSS / S3 / 本地文件系统），技能格式统一为 SKILL.md。

工作流

会话捕获→ 技能提取→ 去重改进→ PRM 验证→ 共享分发

进化引擎

  • workflow：固定 3 阶段 LLM pipeline（摘要 → 聚合 → 执行）
  • agent：OpenClaw 驱动的 Agent 工作空间，直接编辑技能

兼容性与亮点特性

原生集成的 Agent 框架

Hermes Codex Claude Code OpenClaw QwenPaw IronClaw PicoClaw ZeroClaw NemoClaw 任何 OpenAI 兼容 API

关键亮点

  • 零感知使用 — 正常聊天即可，技能进化后台静默进行
  • 多 Agent 统一库 — 前端/后端/数据 Agent 技能互相促进
  • 跨设备同步 — 家/公司/学校各处经验统一
  • 团队集体进化 — N 用户实战经验汇入同一流水线
  • 可选 PRM 评分 — 基于过程奖励模型的质量把关

推荐方案

  • 每成员在各自机器运行 Client Proxy（拦截本地 Agent 请求）
  • 服务器运行 Evolve Server + 共享存储 + 模型代理转发层
  • 模型代理建议用 LiteLLM 或 One API 统一管理 Key 和路由
  • 客户端 llm_api_base 指向服务器代理地址

"只在服务器部署一套 Client + Server"是否可行？

部分可行，但不推荐。

✗ 所有人工作环境耦合在同一台机器，会话互相干扰

✗ 无法利用成员本地环境上下文（代码、终端等）

✗ Agent 无法直接操作成员本机文件和工具

推荐：每人本地 Client + 服务器 Evolve Server + 共享存储 + 模型代理
