# 虚拟环境初始化问题修复说明

**修复日期**: 2026-06-12  
**问题类型**: Windows 系统下 Python 虚拟环境创建失败  

---

## 问题描述

在 Windows 系统上执行 Skill 时，LLM 尝试运行以下命令失败：

```bash
.venv/bin/python -m skills.data_search.scripts.resolve_entity --name "小红书公司" --intent order_summary
```

错误信息：
```
'.venv' 不是内部或外部命令，也不是可运行的程序或批处理文件
```

第二次尝试（自动适配 Windows 路径）：
```bash
.venv\Scripts\python.exe -m skills.data_search.scripts.resolve_entity --name "小红书公司" --intent order_summary
```

错误信息（乱码）：
```
ϵͳҲָ·
```

**乱码解码**：这是 GBK 编码的中文 "系统找不到指定的路径"，说明 `.venv\Scripts\python.exe` 文件不存在。

**根本原因**：
1. **workDir 未设置**：ShellCommandTool 没有指定工作目录，导致 LLM 在错误的目录下执行命令
2. **虚拟环境未创建**：依赖安装可能在 workDir 设置之前执行，或者安装失败

---

## 修复方案

### 1. 设置 workDir（BaseSkillBoxFactory.java）

**修改前**：
```java
ShellCommandTool customShell = new ShellCommandTool(
    null,  // baseDir
    Set.of("uv", "node", "npm", "python", "python3", venvPython),
    command -> { ... }
);
this.skillBox.codeExecution()
    .withShell(customShell)  // ❌ 没有设置 workDir
    .withRead()
    .withWrite()
    .enable();
```

**修改后**：
```java
ShellCommandTool customShell = new ShellCommandTool(
    null,  // baseDir 会被自动覆盖为 workDir
    Set.of("uv", "node", "npm", "python", "python3", venvPython),
    command -> { ... }
);
// ⚠️ 重要：设置 workDir 为仓库根目录
this.skillBox.codeExecution()
    .workDir(localPath.toString())  // ✅ 指定工作目录
    .withShell(customShell)
    .withRead()
    .withWrite()
    .enable();
```

**影响**：LLM 执行 Shell 命令时，会在 `localPath` 目录下执行，这样 `.venv\Scripts\python.exe` 路径才能正确解析。

### 2. 增强虚拟环境验证（DependencyInstaller.java）

#### 2.1 检测并清理损坏的虚拟环境

```java
Path venvPath = workDir.resolve(".venv");
if (Files.exists(venvPath)) {
    // 验证是否为有效的虚拟环境
    boolean isValidVenv = isWindows()
            ? Files.exists(venvPath.resolve("Scripts").resolve("python.exe"))
            : Files.exists(venvPath.resolve("bin").resolve("python"));
    
    if (!isValidVenv) {
        log.warn("Existing .venv is not valid, will recreate...");
        deleteDirectory(venvPath);  // 删除损坏的虚拟环境
    }
}
```

#### 2.2 创建后验证

```java
// 创建虚拟环境
executeCommand(workDir, "uv", "venv", ".venv", "--clear");

// 验证是否成功创建
if (!Files.exists(venvPath)) {
    log.error("Virtual environment was not created at: {}", venvPath);
    return false;
}

// 验证 Python 可执行文件是否存在
boolean isValidVenv = isWindows()
        ? Files.exists(venvPath.resolve("Scripts").resolve("python.exe"))
        : Files.exists(venvPath.resolve("bin").resolve("python"));

if (!isValidVenv) {
    log.error("Python executable not found. Corrupted venv.");
    return false;
}
```

#### 2.3 新增辅助方法

```java
/**
 * 递归删除目录及其所有内容
 */
private static void deleteDirectory(Path directory) throws IOException {
    if (!Files.exists(directory)) {
        return;
    }

    try (Stream<Path> walk = Files.walk(directory)) {
        walk.sorted(Comparator.reverseOrder())
                .forEach(path -> {
                    try {
                        Files.delete(path);
                    } catch (IOException e) {
                        log.warn("Failed to delete: {}", path, e);
                    }
                });
    }
}
```

## 关于 Windows 控制台乱码

### 现象
在 Windows 系统上，错误信息显示为乱码：
```
ϵͳҲָ·
```

### 原因
Windows 控制台默认使用 GBK 编码，而 Java 日志输出使用 UTF-8 编码，导致中文显示为乱码。

### 解码方法
乱码 "ϵͳҲָ·" 实际上是 "系统找不到指定的路径" 的 GBK 编码被误读为 UTF-8。

### 解决方案（可选）
如果需要解决乱码问题，可以：

1. **设置 JVM 参数**：
   ```bash
   java -Dfile.encoding=GBK --enable-preview -jar uagent.jar
   ```

2. **修改控制台编码**：
   ```bash
   chcp 65001  # 切换到 UTF-8
   ```

3. **忽略乱码**：核心问题是路径不存在，乱码不影响功能修复。

**注意**：本次修复主要解决路径问题，乱码是次要问题。
